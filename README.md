# Strop & Steel

Демонстраційний сайт барбершопу з онлайн-записом і кабінетом майстра.
Українська мова за замовчуванням, англійська доступна за адресою `/en`.

Бекенду немає: розклад генерується детерміновано для кожного дня, а записи,
створені в браузері, зберігаються в `localStorage`. Барбершоп, люди та записи
вигадані.

## Сторінки

| Адреса | Що там |
| --- | --- |
| `/`, `/en` | Лендінг: послуги та ціни, барбери, роботи, відгуки, контакти, найближчі вільні крісла наживо |
| `/book`, `/en/book` | Запис у п'ять кроків: послуги, барбер, дата й час, контакти, квиток |
| `/admin`, `/en/admin` | Кабінет майстра: розклад дня, показники, зміна статусів, перенесення, швидкий запис, каталог клієнтів |

Запис, зроблений на `/book`, одразу з'являється в `/admin` і займає час у
розкладі, зокрема в іншій вкладці браузера.

## Запуск

Потрібен Node.js 20.9 або новіший.

```bash
npm install
npm run dev        # http://localhost:3000
```

Інші команди:

```bash
npm run build      # статична збірка в теку out/
npm run typecheck  # перевірка типів
npm run lint       # ESLint
```

## Структура

```
src/
  app/                  маршрути: (uk) для /, (en) для /en, спільні стилі та шрифти
  components/
    ui/                 базові компоненти (shadcn/ui на Radix)
    shared/             оболонка сторінки, логотип, перемикач мови
    landing/            секції лендінгу
    booking/            BookingWizard і його кроки
    admin/              кабінет майстра
  i18n/                 словники uk/en, форматування цін, дат і тривалості
  lib/
    types.ts            інтерфейси та Zod-схеми: Service, Barber, BookingSlot, Appointment
    mock-data.ts        салон, послуги, барбери, генератор записів
    availability.ts     години роботи й розрахунок вільних слотів
    booking-store.ts    сховище записів у localStorage
    booking-api.ts      імітація серверних операцій із повторною перевіркою слота
```

## Розгортання на GitHub Pages

Сайт збирається як статичний (`output: "export"`). Після кожного пуша в `main`
його публікує workflow `.github/workflows/deploy.yml`. У налаштуваннях
репозиторію в розділі **Pages** має бути вибране джерело **GitHub Actions**.

Шлях `/<назва-репозиторію>` підставляється автоматично через змінну
`NEXT_PUBLIC_BASE_PATH`, тож змінювати код під назву репозиторію не потрібно.
